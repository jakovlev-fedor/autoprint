# AutoPrint

Windows-приложение для пакетной печати проектной документации из AutoCAD.
Программа выбирает актуальные версии DWG, определяет листы через DXF, запускает
публикацию через AutoCAD, нарезает общий PDF и раскладывает готовые файлы по
папкам объектов.

## Возможности

- GUI на `CustomTkinter` для выбора проектов и объектов.
- Автоматическая фильтрация версий чертежей.
- Определение листов DWG через ODA File Converter и `ezdxf`.
- Генерация DSD-файла для пакетной публикации.
- Печать через AutoCAD COM-интерфейс.
- Проверка стабильности и количества страниц общего PDF.
- Разделение PDF по чертежам и раскладка результатов по объектам.
- Обновление ядра без перекомпиляции `print.exe`.

## Требования

- Windows 10/11 x64.
- Python 3.10 или новее для запуска из исходников и сборки.
- Установленный и лицензированный AutoCAD с COM-интерфейсом.
- ODA File Converter 27.1.0 или совместимая версия.
- Настроенный в AutoCAD параметр листа `АЗ для презентации`.
- Профиль AutoCAD `<<Профиль без имени>>`, либо измените `ACAD_PROFILE` в
	`core/orchestrator.py`.

Путь к ODA по умолчанию:

```text
C:\Program Files\ODA\ODAFileConverter 27.1.0\ODAFileConverter.exe
```

Если ODA установлена в другое место, измените `ODA_PATH` в
`core/orchestrator.py`.

## Установка зависимостей

В PowerShell из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install customtkinter pywin32 ezdxf pypdf psutil pyinstaller
```

Если PowerShell запрещает запуск скриптов виртуального окружения, активируйте
его из `cmd.exe` командой `.venv\Scripts\activate.bat` или запускайте Python
напрямую через `.venv\Scripts\python.exe`.

## Настройка `CorePath`

Файл `config/config.ini` должен содержать путь к папке, где лежат файлы ядра:

```ini
[Paths]
CorePath = J:\Soft\autoprint\core\
```

`CorePath` может быть локальным или сетевым путем. GUI читает этот путь рядом
с `print_runner.py` или с собранным `print.exe`. Ядро загружается динамически
при каждом запуске pipeline, поэтому изменения в `core/` не требуют сборки GUI.

## Запуск из исходников

```powershell
python print_runner.py
```

Для рабочего запуска обычно используется отдельная папка проекта:

```text
ИМЯ_ПРОЕКТА/
└── !_Печать/
		├── print.exe
		└── config/
				└── config.ini
```

При старте приложение сканирует корень проекта, позволяет включить или
исключить объекты и запускает полный процесс кнопкой `Pipeline (Авто)`.

## Сборка `print.exe`

Быстрая сборка:

```powershell
python -m PyInstaller --onefile --windowed --name print print_runner.py
```

Сборка по зафиксированной конфигурации проекта:

```powershell
python -m PyInstaller print.spec
```

Готовый файл находится в `dist/print.exe`. Скопируйте его в
`ИМЯ_ПРОЕКТА\!_Печать\`, а рядом создайте `config\config.ini` с корректным
`CorePath`.

## Pipeline

Полный запуск выполняется в следующем порядке:

1. **М1: Path Collector** — GUI проверяет доступность выбранных путей.
2. **М2: Version Filter & Layout Mapper** — выбираются максимальные версии
	 DWG, выполняется конвертация в DXF и формируется `tmp\map.json`.
3. **М3: DSD Generator** — создается DSD-файл в `.dsd файлы\`.
4. **М4: AutoCAD Print Engine** — AutoCAD публикует общий PDF в
	 `tmp\monolithic_output.pdf`.
5. **М5: PDF Distributor** — общий PDF делится на отдельные файлы и сохраняется
	 в `Версии\` и `! ГОТОВО\`.

Критическая ошибка останавливает pipeline. При предупреждении М4 модуль М5 не
запускается, чтобы не распространять неполный результат.

## Рабочая структура проекта

Рядом с `print.exe` приложение ожидает следующую структуру:

```text
ИМЯ_ПРОЕКТА/
└── !_Печать/
		├── print.exe
		├── config/config.ini
		├── .dsd файлы/                 # DSD-файлы текущих сессий
		├── tmp/
		│   ├── dwg/                    # временные DWG
		│   ├── dxf/                    # временные DXF
		│   ├── map.json                # карта печати
		│   └── monolithic_output.pdf   # общий PDF
		├── Версии/
		│   └── autoprint_vN/           # архив результатов сессии
		└── ! ГОТОВО/                   # актуальные результаты
```

В начале каждой сессии `tmp/` очищается. Папка `! ГОТОВО/` очищается перед
записью нового результата. Архивы в `Версии/` сохраняются.

## Формат входных данных

Для анализа используются папки проектов и объектов с подпапкой `Рабочая`.
Папки, в имени которых есть `!`, исключаются из сканирования.

Имена чертежей должны содержать код заявки и номер версии. Код заявки
распознается по шаблону:

```text
[A-Za-z]{2,5}-[A-Za-z]-[A-Za-z]-[A-Za-z]{2,5}-\d{4}
```

Версия распознается по обозначению `_В1_`, `_в2_`, `_В3` или аналогичному.
Для каждой группы в печать попадает чертеж с максимальным номером версии.

Пример результата:

```text
! ГОТОВО/
└── Объект_А/
		└── LUK-S-P-RUS-0429_В2.pdf
```

## Разработка ядра

`print_runner.py` не содержит бизнес-логики. Он загружает
`core/orchestrator.py` через `importlib`, а оркестратор по очереди загружает
модули `module2`–`module5`.

Изменения в `core/` можно проверять без перекомпиляции:

```powershell
python print_runner.py
```

Пошаговые методы оркестратора (`run_module2`, `run_module3`, `run_module4`,
`run_module5`) предназначены для диагностики отдельных этапов. Для обычной
печати используйте `run_pipeline` через GUI.

## Проверка перед запуском

- Доступны AutoCAD и ODA File Converter.
- В `config.ini` указан существующий `CorePath`.
- В AutoCAD существует параметр листа `АЗ для презентации`.
- Выбранные папки доступны для чтения.
- В папках `Рабочая` находятся DWG с распознаваемыми кодами и версиями.
- AutoCAD не заблокирован другим процессом печати.

## Устранение проблем

**Ошибка загрузки ядра**

Проверьте `CorePath`, наличие `orchestrator.py` и остальных файлов в папке
ядра. Для сетевого пути проверьте доступность диска в той же учетной записи,
из-под которой запускается `print.exe`.

**ODA не запускается**

Проверьте `ODA_PATH` в `core/orchestrator.py` и наличие прав на чтение и запись
временной папки.

**AutoCAD не публикует PDF**

Проверьте, что AutoCAD установлен, доступен через COM и содержит параметр
`АЗ для презентации`. Подробный статус и лог доступны в окне приложения.

**Получен неполный результат**

Проверьте `tmp\map.json`, `tmp\monolithic_output.pdf` и DSD-файл в
`.dsd файлы\`. Эти файлы сохраняются при критической ошибке и помогают
определить остановившийся этап.

## Ограничения

Приложение рассчитано на Windows и интеграцию с AutoCAD. В репозитории нет
формального автоматизированного набора тестов, поэтому перед изменением
логики печати следует проверять pipeline на тестовом проекте и сохранять
артефакты из `tmp/` при ошибках.
